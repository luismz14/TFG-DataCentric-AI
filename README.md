# Data-Centric AI for Multiclass Colorectal Polyp Histology Classification

This repository contains the completed Bachelor's Final Degree Project on Data-Centric AI for multiclass colorectal polyp histology classification from colonoscopy images and videos.

The project investigates whether improving **dataset construction, video-derived data ingestion, and temporal curation** can improve classification performance while keeping the classifier families fixed. Two architectures were evaluated: **EfficientNet-B0** and **ViT-Small**.

The four target histology classes are:

- Adenoma
- Sessile serrated adenoma (SSA)
- Hyperplastic
- Adenocarcinoma

**Technology stack:** Python · PyTorch · timm · Ultralytics YOLO · ByteTrack · OpenCV · scikit-image

## Key Results

- **EfficientNet-B0** achieved its best validation Macro-F1 with confidence-based ingestion: **0.5864** versus **0.5371** for the baseline, an approximately **+9.18% relative improvement**.
- **ViT-Small** achieved validation Macro-F1 with final deduplication: **0.6233** versus **0.5949** for the baseline, an approximately **+4.77% relative improvement**.
- These validation improvements did **not consistently transfer to the external multicenter test set**, highlighting domain shift between the training and external evaluation domains.

## Problem and Data-Centric Approach

The project studies multiclass histology classification in a setting where the available clinical data include both still images and colonoscopy videos.

Instead of repeatedly changing the classifier architecture, the main intervention is the **data pipeline**:

1. normalize and crop the original image repository;
2. create leakage-aware grouped train/validation splits;
3. generate additional training samples from colonoscopy videos;
4. investigate data-quality filtering and temporal redundancy removal;
5. compare controlled dataset variants using the same classifier families.

This allows the contribution of the data-centric stages to be evaluated independently from major architectural changes.

## Pipeline

### Phase 0: Normalization and Grouped Splitting

Phase 0 prepares the image repository before training.

It includes:

- automatic removal of black image borders;
- normalized clinical image crops;
- metadata preparation;
- grouped train/validation splitting using patient- and examination-related information to reduce data leakage between related samples.

The validation split is kept fixed for the subsequent experimental phases.

### Phase 1: Image-Classification Baselines

Phase 1 establishes the reference classification performance using the normalized image dataset.

Two ImageNet-pretrained architectures are evaluated:

- **EfficientNet-B0**
- **ViT-Small**

The same general training and evaluation framework is maintained across later dataset variants so that changes in performance can be attributed primarily to the data pipeline.

### Phase 2: Video-Based Dataset Ingestion

Phase 2 expands the training data using frames extracted from colonoscopy videos.

The ingestion workflow combines:

- **YOLO-based polyp detection**;
- **ByteTrack-assisted temporal association**;
- temporal sampling around known lesion observations;
- detector-confidence information;
- dataset construction under different ingestion strategies.

The public dataset-generation entry points are implemented in:

- `src.phase2.experiment.ingest_phase2_dataset()`
- `src.phase2.experiment.ingest_phase2_confidence_only_dataset()`

Two main ingestion strategies were evaluated:

- **Balanced ingestion**, designed to reduce the original class imbalance;
- **Confidence-based ingestion**, where candidate frames are selected according to detector confidence.

The Phase 2 notebooks operate on datasets generated by this source workflow:

- `phase2.ipynb` trains and compares EfficientNet-B0 models;
- `phase2ViT.ipynb` trains and compares ViT-Small models.

The notebooks therefore do **not** perform the original video-ingestion step themselves.

Phase 2 is configured around **GPU device 0** and **half-precision inference**. CPU execution of the complete Phase 2 ingestion workflow has not been validated.

### Phase 3: Data Curation and Temporal Deduplication

Phase 3 investigates several forms of data curation, including:

- image-quality filtering;
- model-guided filtering;
- temporal redundancy removal.

The quality and model-guided filters remained exploratory. The final selected Phase 3 configuration focuses on **temporal deduplication**.

For each source dataset, the final deduplication strategy derives adaptive similarity thresholds from the observed comparable pairs:

- **SSIM threshold:** 75th percentile of comparable-pair SSIM values;
- **pHash distance threshold:** 25th percentile of comparable-pair perceptual-hash distances;
- **temporal grouping window:** 2.0 seconds.

Two samples are considered redundant only when **both** similarity conditions are satisfied:

```text
SSIM >= SSIM threshold
AND
pHash distance <= pHash threshold
```

Fixed SSIM/pHash values present in tuning notebooks or helper defaults are not the final experimental configuration.

Within redundancy groups, representative samples are selected using a quality score:

```text
Q =
    0.30 * normalized sharpness
  + 0.20 * normalized bounding-box area
  + 0.50 * detector confidence
```

The resulting retention process is adaptive to the dataset and class distribution rather than applying a single global fixed-number rule.

## Final Evaluation

Performance is evaluated using **Macro-F1** on:

- the fixed validation split;
- an external multicenter test set.

Each configuration is evaluated over four random seeds:

```text
42, 123, 456, 789
```

The following values are the final thesis results, reported as **mean Macro-F1 ± standard deviation** over the four seeds.

| Configuration              | EfficientNet-B0 Validation | EfficientNet-B0 External Test | ViT-Small Validation | ViT-Small External Test |
| -------------------------- | -------------------------- | ----------------------------- | -------------------- | ----------------------- |
| Baseline                   | 0.5371 ± 0.0349           | 0.4911 ± 0.0056              | 0.5949 ± 0.0104     | 0.4816 ± 0.0123        |
| Confidence filtering (conf >= 0.4) | 0.5674 ± 0.0059           | 0.5003 ± 0.0082              | 0.6196 ± 0.0087     | 0.4637 ± 0.0180        |
| Deduplication (conf >= 0.4) | 0.5713 ± 0.0105           | 0.5003 ± 0.0142              | 0.6160 ± 0.0103     | 0.4909 ± 0.0065        |
| Confidence-based ingestion | 0.5864 ± 0.0100           | 0.4895 ± 0.0055              | 0.6179 ± 0.0032     | 0.4476 ± 0.0154        |
| Final deduplication        | 0.5830 ± 0.0048           | 0.4917 ± 0.0098              | 0.6233 ± 0.0186     | 0.4653 ± 0.0184        |

The table presents selected historical configurations. The [aggregate results summary](docs/results-summary.csv) preserves all six configurations in the archived summary, including the Phase 2 `train` branch. See [reproducibility and provenance notes](docs/reproducibility.md) for configuration mapping and an outstanding interpretation review.

### Interpretation

For **EfficientNet-B0**, final deduplication increases validation Macro-F1 from **0.5371 to 0.5830**, approximately **+8.55% relative to baseline**.

The best EfficientNet-B0 validation result is obtained with **confidence-based ingestion**, reaching **0.5864**, approximately **+9.18% relative to baseline**.

For **ViT-Small**, final deduplication increases validation Macro-F1 from **0.5949 to 0.6233**, approximately **+4.77% relative to baseline**, within the selected configurations shown above.

However, the external-test results do not show the same consistent improvement.

The experiments therefore support two main conclusions:

1. the data-centric pipeline can improve classification performance within the training/validation domain;
2. these gains do not automatically translate to a different clinical domain.

The multicenter external evaluation exposes a domain shift between the predominantly single-domain training data and data acquired in different clinical environments and imaging systems. Improving external generalization would require more representative multicenter data during model development rather than relying only on post-hoc data curation.

## Installation

The source code requires **Python 3.10 or newer**. Python **3.11** is the recommended reference version.

Create a virtual environment:

```bash
python -m venv .venv
```

Activate it on Windows PowerShell:

```powershell
.venv\Scripts\Activate.ps1
```

Or on Unix-like systems:

```bash
source .venv/bin/activate
```

Install the project dependencies:

```bash
pip install -r requirements.txt
```

The dependency file contains the direct project dependencies but does not claim bit-for-bit recreation of the original training environment. Exact historical package versions were not recoverable from the completed project repository.

## Running the Workflow

The tracked notebooks can be opened with:

```bash
jupyter notebook <notebook.ipynb>
```

The logical experimental order is:

1. `phase0.ipynb`
2. `phase1.ipynb` or `phase1ViT.ipynb`
3. generate the required Phase 2 datasets through `src/phase2/experiment.py`
4. `phase2.ipynb` or `phase2ViT.ipynb`
5. `phase3.ipynb`, `phase3ViT.ipynb`, or `phase3_sweep.ipynb`
6. `final_results.ipynb`

The repository does not provide a separate command-line interface for Phase 2 ingestion. Dataset generation is exposed through the Python functions in `src.phase2.experiment`.

`final_results.ipynb` analyzes previously generated experiment artifacts and therefore requires the corresponding local results.

The classifier implementations use ImageNet-pretrained EfficientNet and ViT weights. A first execution may require network access to obtain these pretrained weights if they are not already available locally.

## Data and Reproducibility Limitations

The public repository intentionally excludes:

- clinical images;
- colonoscopy videos;
- patient-related metadata;
- private dataset inventories;
- generated result directories;
- classifier checkpoints;
- credentials and local environment files.

Full experimental reproduction therefore requires private clinical data that cannot be distributed with this repository.

The public repository provides the source code, configurations, notebooks, and experimental structure needed to inspect the methodology, but it should **not** be considered a self-contained reproduction package.

## External Detector Setup

Phase 2 uses the third-party YOLO checkpoint:

`CVC_ClinicDB_yolov8m.pt`

The checkpoint originates from the [YOLO_SAM2](https://github.com/sajjad-sh33/YOLO_SAM2) project.

Exact upstream checkpoint:

[CVC_ClinicDB_yolov8m.pt](https://github.com/sajjad-sh33/YOLO_SAM2/blob/main/YOLO_Checkpoints/CVC_ClinicDB_yolov8m.pt)

The binary is intentionally **not redistributed** in this repository.

For Phase 2 ingestion, create `utils/model/` if necessary and place the checkpoint at:

```text
utils/model/CVC_ClinicDB_yolov8m.pt
```

The optional Dropbox utilities similarly require local credentials, which are never stored in the repository.
